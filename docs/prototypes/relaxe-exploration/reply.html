FIRST REPLY PROPOSAL

Reply here.
Or open a screen.

Settings will offer Separate screen or Inline below comment. Inline is the selected default. Use the style control above to compare. In the inline version, tap Reply below either comment; the editor opens immediately underneath it. Only one editor is open at a time in this proposal.

The separate screen keeps the compact parent preview, with Expand / Collapse. These controls expand that post/comment only; they do not load a comment thread. Compact parent display is selected; Expand / Collapse remains available.

Close offers Save draft, Leave without saving and Cancel when text exists. Leaving without saving keeps any older saved draft. Empty close removes that target’s saved text. Save draft restores writing and image/GIF selections for the same account and parent, as selected. This page-memory demonstration shows the required behavior; Android storage still needs later implementation.

GIF beside Images, with Italic in More, is selected. Its picker inserts a bundled sample at the current selection; Preview shows a paused image. More keeps less-used formatting. Images now opens a reusable list with Choose image and Take photo. Thumbnail-and-filename rows are selected; selecting a row inserts the same image again. Samples insert immediately, with selection/camera/upload/processing failure fixtures. The account stays fixed while image metadata is present; this guard is a proposal. Removing an image block keeps the sample available for reuse. Saved drafts now restore the sample list and image/GIF selections together with the writing. Real upload timing, cancellation and restoration are not modeled. Real provider/upload flows, richer Markdown/parent rendering, selection/copy and restoration use the existing native mechanisms in a later implementation. No post type, subreddit picker, flair or post-only options appear in Reply.

The GIF fixture models one selected descriptor, matching the native single-GIF field; it does not establish support for several independently selected GIFs. The descriptor is now included in the browser draft snapshot. The native draft key is parent fullname + reply/edit type, without an account key; text storage also omits uploaded-image/GIF metadata. Account/parent/type keys in this browser demonstrate the selected isolation; native account isolation and attachment recovery remain unimplemented. Reuse the native ViewModel/send helper and resolve those boundaries before Android implementation.
